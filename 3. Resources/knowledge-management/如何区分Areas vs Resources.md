很多人在用 **PARA** 的时候都会遇到 **Areas 和 Resources 边界模糊**的情况。  
其实 Tiago Forte 在 _Building a Second Brain_ 里有过非常清晰的区分逻辑，我们可以用几个维度来判断：

---

# 🗂 如何区分 **Areas（领域）** vs **Resources（资源）**

## 1. 定义上的核心区别

- **Areas（领域）** = 你持续负责、需要维持一定标准的生活或工作范畴  
    → 它和你的「责任」绑定。
    
- **Resources（资源）** = 你感兴趣的、未来可能用得上的主题或知识  
    → 它和你的「兴趣」绑定。
    

📌 **关键点**：

- 如果它失败了，你会感到「我没尽到责任」 → 属于 **Area**
    
- 如果它丢了，只是少了一个可能有用的参考 → 属于 **Resource**
    

---

## 2. 举例区分

### ✦ 健康

- **Areas**: 健康管理（保持运动、定期体检、合理饮食）
    
- **Resources**: 健身动作库、饮食研究论文、跑步技巧笔记
    

### ✦ 编程技能

- **Areas**: 前端开发能力（持续保持能交付项目的水平）
    
- **Resources**: Next.js 教程、React 高级模式文章、TypeScript 学习清单
    

### ✦ 工作

- **Areas**: 团队管理、财务合规、客户关系
    
- **Resources**: 管理学书籍、沟通技巧资料、财务建模工具
    

---

## 3. 边界判断法

如果你拿到一条信息，不知道放哪，可以问自己三个问题：

1. **这是我持续需要保持的吗？**
    
    - 如果是 → Area
        
    - 如果只是「可能以后用」 → Resource
        
2. **如果我不维护它，会不会有后果？**
    
    - 有责任和后果 → Area
        
    - 没有后果，只是少了点参考 → Resource
        
3. **它和我当前的角色/责任直接相关吗？**
    
    - 相关 → Area
        
    - 不相关，仅仅是兴趣 → Resource
        

---

## 4. 经验法则

- **Areas 稳定但少**（一般 5–15 个，比如健康、职业、财务、人际关系）。
    
- **Resources 可以很多**（几十个、上百个，比如各种你感兴趣的学习主题）。
    
- **不确定时，先放 Resource** → 等它逐渐成为你「必须负责的事」，再提升为 Area。
    

---

📌 总结一句话：

- **Areas = 责任 / 持续维持**
    
- **Resources = 兴趣 / 未来参考**
    
- **不确定时，先放 Resource，再升级到 Area**
